# Submission Safety Policy

Apply this policy to Crux Mathematicorum and every other journal, problem column, repository, preprint server, website, or email submission.

## Authorization Boundary

- Treat research, file generation, and local packaging as separate from external transmission.
- Fill or upload only when the user's current request explicitly asks for it.
- Uploading files or entering author details sends data to a third party. Confirm the intended files and page before doing so.
- A request to “prepare”, “draft”, or “make files” does not authorize form filling or upload.

## Human-Only Final Actions

Never perform any of the following for the user:

- tick originality, copyright, authorship, consent, or author-responsibility declarations;
- click Finish, Submit, Publish, Send, Confirm submission, or an equivalent final action;
- send a submission email;
- approve terms or licenses;
- represent that the user personally reviewed a statement.

These remain human actions even when the checkbox or button appears routine.

## Pending-Confirmation State

When explicitly authorized, the safe stopping point is:

- author metadata filled;
- category selected;
- intended files uploaded and upload completion visible;
- optional editor comment filled;
- declarations unchecked;
- final button untouched.

Before stopping, inspect the visible page and report any uncertainty. Do not infer successful upload solely from selecting a file.

## Crux-Specific Notes

- Submit one proposal or one solution per submission.
- Use a proposal category only for a new problem; use a solution category for an existing problem and identify its exact number.
- The comment should name or summarize the submitted problem so editors can identify it. Avoid novelty claims.
- Upload both the LaTeX source and compiled PDF when accepted by the current form. Add only relevant figures or reproducibility files.
- Keep the author's contact email out of the public PDF unless explicitly requested.
